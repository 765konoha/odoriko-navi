# 小道具スプレッドシート連携 設計メモ

小道具担当が管理している Google スプレッドシート(「2026」シート)から、
ボタンひとつで踊り子ナビへ反映する仕組みの設計。

## 方針

- アプリで扱う受け渡しは **お祭り当日のお持ち帰りだけ**。案件や急な移動を含む
  保管・リレー全般はスプレッドシートが正。
- アプリは「祭り当日の受け渡し」と「現時点の保持者・状態」を記録する。
- データの流れはスプレッドシート → アプリの一方向。スプレッドシート側
  (Apps Script)から送るので、シートの共有は「制限付き」のままでよい。
- 判定(どのセルが誰か・何をするか)はすべてアプリ側
  (`supabase/functions/_shared/propSheet.ts`)。Apps Script は
  「シートを丸ごと送って、返ってきた結果を表示する」だけ。

## 操作

| ボタン | 入力 | すること |
|---|---|---|
| 保有者・状態を更新 | 基準の列(選択式) | D列〜基準の列で、一番右に書かれた人を保有者にする。状態列も反映。アプリに無い小道具は新規登録 |
| 受け渡し予定を反映 | 対象日(日付) | 対象日のお祭りの「持ち帰り」を、その日の受け渡し予定としてアプリに載せる |

- 操作欄は既存の「2026」シートの最上段(行を挿入)に置く。
- PC: ボタン(図形にスクリプトを割り当て)→ 確認結果をポップアップ →「はい」で反映。
- スマホ: 「確認」「反映する」のチェックボックス(インストール型 onEdit トリガー)。
  ポップアップは出せないので、結果欄に書き出す。
- 状態は「2026」シートの備考の右に「状態」列(選択式・色付き)。
- 名前対応表は新しいシート「名前対応表」(A列: スプシでの名前、B列: シリアル)。

## シートの読み方

見出しの行は位置で決め打ちせず、C列の文字で探す。

| C列の文字 | 行の意味 |
|---|---|
| お祭り・イベント | 見出し(お祭り名・「リレー」・「現在の保管者」・「備考」・「状態」) |
| 日付 | 日付 |
| 演舞作品 / ステージ/流し | 見出しの続き(読み飛ばす) |

- それより下で B列(番号)が入っている行が小道具1点。種類は A列(結合セルは上の値を引き継ぐ)。
- D列から「現在の保管者」の手前までが時系列の列。
  - 見出しが「リレー」で始まる列(または見出しが空の列)は、直前のお祭りのリレー列。
  - 「リレー 行き」= 現地に持っていく人、「リレー 帰り」= 持ち帰る人。
  - それ以外の見出しはお祭り(案件)の列。D列は「2025年からの保管者」。
- 日付は「2026/03/22」「8/29・30」「10/10-11」「5/15,17」「2.22」を解釈する。
  年が無いものはシート名の年。日付が読めない列(「光が丘」など)は対象日の指定では選べない。

### セルの読み方

| 書き方 | 保有者の更新 | 当日の持ち帰り(リレー列) | お祭りの列(使う人) |
|---|---|---|---|
| A→B | B | A(当日 A が持ち帰り、後日 B) | A と B |
| A・B、A/B | A と B(一緒に持つ) | A と B | A と B |
| 行:A 帰:B | B | B | A と B |

- ●、◯、○、★、☆ は無視。（ ）の中は無視(ただし「ＮＥＷ（ちえこ）」は ちえこ)。「※」から後ろは無視。
- 空欄・#N/A・✖ は名前なし。「貸出」を含むものは反映しない(スキップ)。

### 保有者の更新

- 各小道具の、D列〜基準の列で一番右の空でないセルを読む。
- 名前が読めたら、その人たちを保有者にする(アプリの保有者と違うときだけ)。
- スキップ・名前なしのときは保有者を変えない。
- 状態列: 空欄・正常 → 正常、破損、故障、紛失、修理中、使用停止。
- 名前も状態も無い行(#N/A の行など)は、アプリに未登録なら登録しない。

### 当日の受け渡し予定

対象日を含むお祭りの列を探す(無い・複数あるときはエラー)。

| スプシの状態 | 持ち帰る人(受け取る人) | 渡す人(表示) |
|---|---|---|
| すぐ右のリレー列(帰りがあれば帰り)に名前がある | その人 | お祭りの列の人 |
| すぐ右のリレー列が空欄 | お祭りの列の人 | 行きの列の人(無ければアプリ上の今の保有者) |
| どちらも空欄 | ― 受け渡しは作らない | |

- 持ち帰る人がアプリ上の今の保有者と同じなら作らない。
- 複数日のお祭りは期間内のどの日でも選べる。アプリには最終日の予定として載せる。
- 同じ日を押し直すと上書き(追加・変更・取り消し)。受け取り済みには触らない。
- 前のお祭りのスプシ由来の予定が残っていれば取り消す。手作業で作った予定が
  残っている小道具はエラーにする。

## 名前の照合

1. 名前対応表(正規化して比較)
2. アプリの名簿(全祭りの festival_participants のニックネーム)
3. シリアルそのもの(例: K-015)

正規化: 全角/半角、ひらがな/カタカナ、大文字/小文字、伸ばし棒の種類(ー ― － − ‐ -)を
同じとみなし、空白を無視する。2人以上に当てはまるときは特定できないものとして扱う。

## エラー表示

- 「提灯 白①（12行目）の行の「あすこ」について、特定ができませんでした。表記をアプリ上の名簿と一致させるようにしてください。」
- 「太鼓 3（96行目）の行の「なお」に当てはまる人が複数います（101・205）。名前対応表でシリアルを指定してください。」
- 「赤白布「予備」が2行あります（92・93行目）。番号を区別してください。」
- エラーの小道具だけ反映せず、ほかは反映できる(PC は確認ダイアログで選ぶ)。

## アプリ側の構成

| もの | 中身 |
|---|---|
| `supabase/functions/_shared/propSheet.ts` | 正規化・セルの解釈・シートの解析・計画(テストあり) |
| `supabase/functions/props-sheet-sync/index.ts` | 受付口。`x-sync-token` で確認し、計画 → (反映) → 結果を返す |
| `supabase/migrations/0030_prop_sheet_sync.sql` | 受け渡しに `sheet_date`・`giver_serials`、反映用の関数、実行ログ |
| `tools/apps-script/odoriko-navi-props.gs` | スプレッドシートに貼るスクリプト |

- 受付口の秘密情報: Supabase の Edge Function Secrets に `PROPS_SYNC_TOKEN`。
  同じ値を Apps Script のスクリプト プロパティ `SYNC_TOKEN` に入れる。
- スプシ由来の受け渡しは、踊り子の画面では受け渡し先を変更できない(変更はスプシで)。
- 状態の色: 故障・破損=赤、修理中=黄、紛失=紫、使用停止=灰(スプシとアプリで同じ)。

## 導入手順

1. Supabase の SQL Editor で `supabase/migrations/0030_prop_sheet_sync.sql` を流す(何度流してもよい)。
2. Edge Function `props-sheet-sync` を作り、`npm run build:function` で作った
   `dist/functions/props-sheet-sync.ts` を貼ってデプロイする。
   - 「Verify JWT」はオフにする(合言葉で確認するため。呼び出し元は Apps Script だけ)。
3. Edge Function の Secrets に `PROPS_SYNC_TOKEN`(長いランダムな文字列)を登録する。
4. スプレッドシートの「拡張機能 → Apps Script」に `tools/apps-script/odoriko-navi-props.gs` を貼る。
   - 先頭の `ENDPOINT` と `PUBLISHABLE_KEY` をプロジェクトの値にする。
5. スプレッドシートを開き直し、メニュー「踊り子ナビ → 初期設定」で合言葉を登録する
   (Google の許可画面が出たら承認する)。
6. 操作欄の E列に図形を置き、それぞれ `runHoldersFromButton` / `runHandoversFromButton` を割り当てる。

### 「2026」シートの操作欄(最上段に行を挿入)

| 行 | C列 | D列 | E列 | F〜I列 |
|---|---|---|---|---|
| 1 | 踊り子ナビ連携 | 説明 | | |
| 2 | ■保有者・状態を更新 | 基準の列(選択式) | ボタン | F「確認」G☐ H「反映する」I☐ |

スクリプトは C列の「■保有者・状態を更新」「■受け渡し予定を反映」「結果」の文字で操作欄を探す。
